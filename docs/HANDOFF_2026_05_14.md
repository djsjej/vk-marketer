## 🎯 Phase 5 — Спецификация Таргетолога-агента (от Vizit'а 14.05)

Vizit предложил отдельного суб-агента под подключение к **TargetHunter**.
Это внешний сервис который парсит подписчиков VK сообществ и собирает
сегменты по поведению (активные, комментирующие, лайкающие). TargetHunter
выгружает CSV → Vizit грузит в VK Ads «Аудитории» → получается `segments` ID.

### Что должен делать Таргетолог

1. **Принимает от Vizit'а** список целевых VK-сообществ (через Telegram
   команду или env var).
2. **Через TargetHunter API** (нужен API-ключ от Vizit'а, новая env var):
   - Парсит подписчиков всех групп
   - Ищет **пересечения** — кто подписан на 2+ нишевых сообщества
     (самая горячая аудитория для нашей ниши)
   - Фильтрует на **активность** — кто реально комментирует/лайкает
     в выбранный период
3. **Креативит**: предлагает Vizit'у через Claude N разных «связок»
   (группа+интерес) для A/B-тестов. Например:
   - «Подписчики Дивеево + Богородичные иконы»
   - «Активные комментаторы Веруй+Православие + молитвы за здравие»
4. **Выгружает результат** как CSV (готовый для загрузки в VK Ads
   «Аудитории» → сегмент).
5. **Подсказывает Vizit'у в Telegram**: «загрузи этот CSV в Аудитории,
   потом скинь мне ID сегмента, я положу его в `VK_AUDIENCE_SEGMENT_IDS`».

## 🌙 Дополнение от позднего вечера 14.05 — пересмотр Phase 5

### Решение: пишем свой парсер VK API напрямую (не подключаем TargetHunter)

Исследование за вечер показало:

- **У TargetHunter нет публичного REST API** для парсинга — только UI с
  «автозадачами» (внутренняя автоматизация по расписанию внутри их
  интерфейса). Vizit написал в их круглосуточную поддержку с прямым
  вопросом про API, ответ пришёл «вы хотите автозадачу настроить?» —
  то есть открытого API для разработчиков они не предлагают.
- **У Pepper.Ninja тоже нет публичного API.** Они с TargetHunter
  официально партнёры с аналогичным функционалом, и видимо это общая
  особенность рынка русских VK-парсеров — продают UI, API держат
  закрытым.
- **VK сам предоставляет открытый API** через `api.vk.com/method/...`
  — все нужные методы публичные: `groups.getMembers` (подписчики
  сообщества), `wall.get` (посты), `users.getSubscriptions` (на что
  подписан человек). Пересечения и фильтры активности — делаем у себя
  через set-операции в Python.

**Решение Vizit'а:** идём по пути своего парсера на VK API напрямую,
без посредников.

### VK Service Token в Railway

Vizit положил **«Сервисный ключ доступа»** из настроек приложения в
Railway env `VK_API_SERVICE_TOKEN`. Это серверный токен для
без-авторизованного доступа к публичным VK API методам.

**Ограничения service token (важно знать для нового чата):**
- Доступны только методы публичных данных. Подходит для:
  `groups.getMembers`, `wall.get`, `groups.getById`, `users.get`.
- НЕ подходит для (потребуют user token через OAuth):
  `likes.getList`, `users.getSubscriptions`, `friends.get`.
- Rate limit 5 запросов/секунду на токен.
- Закрытые сообщества не парсятся (VK сам возвращает ошибку).

**Что это значит для архитектуры:** на MVP — service token хватает
(собрать подписчиков сообщества + найти пересечения). На фильтр
по активности (комментаторы/лайкеры) — придётся либо запросить user
token через PKCE-flow позже, либо использовать `wall.get` чтобы
получить посты и парсить `comments.count` / лайки на стороне сервера.
