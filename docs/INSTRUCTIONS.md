## 🧪 Самотестирование через respx

respx позволяет мокать любой HTTP-запрос httpx. Каждое изменение которое
затрагивает HTTP должно быть покрыто тестом который проверяет:
1. Мы шлём правильный payload (структура полей)
2. Мы корректно парсим ответ (включая разные форматы)
3. Мы корректно обрабатываем ошибки (4xx, 5xx)

### Шаблон теста для нового endpoint

```python
@pytest.mark.asyncio
@respx.mock
async def test_endpoint_sends_correct_payload():
    respx.post(OAUTH_URL).mock(
        return_value=httpx.Response(200, json={"access_token": "tk", "expires_in": 86400})
    )
    route = respx.post(f"{VK_API_BASE}/<endpoint>.json").mock(
        return_value=httpx.Response(200, json={"id": 123})
    )
    client = VKAdsClient(authenticator=VKAdsAuthenticator(...))
    result = await client.<method>(...)
    body = json.loads(route.calls[0].request.read())
    assert body["..."] == "..."
    assert result["id"] == 123
```

## 📖 Декодер ошибок VK Ads (обновлено в v1.1)

VK возвращает структурированные ошибки. Если код мне непонятен — **сразу
запрашиваю у Vizit'а** страницу `info "Коды ошибок"` (URL:
`https://ads.vk.com/doc/api/info/Коды%20ошибок`), а не гадаю.

### Структура error response

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Validation failed",
    "fields": {
      "<field>": {
        "code": "<error_code>",
        "message": "<human_message>",
        "arguments": {...}
      }
    }
  }
}
```

### Известные коды (что уже знаю)

| code | Что значит | Типичный фикс |
|---|---|---|
| `required` | Поле обязательно | Добавить поле в payload |
| `empty_value` | Пустое значение | Заполнить значение |
| `unallowed_value` | Значение вне диапазона | Проверить min/max, формат |
| `min_value` | Меньше минимума | Например budget_limit_day < 100₽ |
| `bad_value` | Невалидное значение | VK часто даёт валидные в `arguments` |
| `bad_items` | Что-то в массиве плохое | Чинить элементы списка по индексу |
| `object_validation` | Объект внутри списка невалидный | Декодировать nested fields |
| `unknown_resource_field` | Поле не существует в API | Удалить или переименовать |
| `ad_object_not_found` | URL не зарегистрирован | Зарегистрировать через `/api/v1/urls/` |
| `token_limit_exceeded` | 5+ токенов на client_id | `/clean_tokens` или email support |

## 🧠 Принцип суб-агентов (новое в v1.2)

Когда задача требует **узкого специализированного знания** (изучение API,
парсинг данных, мониторинг, тестирование, креативы) — **я сам предлагаю
создать суб-агента** под эту задачу. Не пытаюсь сам всё делать.

Каждый агент = отдельный модуль с:
- Собственной личностью (`src/<agent>/persona.py`)
- Узкой зоной ответственности
- Read-only либо write только в свою область
- Рапортами мне (Claude), а я перевожу Vizit'у

**Правила:**
- Один агент = одна задача. Не размазывать.
- Агент НЕ лезет в чужие модули.
- Агент НЕ инициирует POST/PUT в VK без подтверждения Claude.
- Я (Claude) НЕ делегирую агенту критические решения — он мне помощник,
  не замена.

**Существующие и планируемые агенты:**

| Агент | Зона | Фаза |
|---|---|---|
| Биба (`src/biba/`) | Карта функционала VK Ads | Phase 5 |
| Аналитик | Метрики, инсайты, утренние отчёты | Phase 4 |
| Креативщик | A/B варианты текстов и креативов | Phase 4.5 |
| Сторож | Auto-pause/auto-scale кампаний | Phase 4 |
| Конкурент | Парсинг чужих кампаний | Phase 7 |

**Когда предлагать нового агента:**
- Задача займёт >100 строк кода и логически отдельна
- Это периодическая операция (мониторинг, отчёты)
- Это специализированное знание которое не используется в основном потоке
