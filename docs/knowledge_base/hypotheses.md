# Гипотезы на проверке

Предположения которые ждут реальной проверки в тестах. Это **рабочая
очередь** организации — каждый цикл берём приоритетные, тестируем,
переносим в working_combos или failed_combos в зависимости от результата.

## Формат записи

```markdown
## H<номер>: <короткое утверждение>

**Дата создания:** YYYY-MM-DD
**Автор:** Боба / Vizit / Алина / Claude
**Статус:** ожидает теста | в работе | подтверждено | опровергнуто

**Гипотеза:** Развёрнутое утверждение которое проверяем.
Например: «Женщины 45-58 которые подписаны на 2+ правосл. сообществ
кликают на креатив с темой Радоницы лучше чем на общую тему
поминовения, потому что в Радоницу есть конкретный повод».

**Как проверить:**
- Сегмент: пересечение подписчиков 2+ правосл. сообществ + ж45-58
- Креатив A: общая тема поминовения
- Креатив B: тема Радоницы (за 5 дней до неё)
- Бюджет: 500₽ на каждый креатив = 1000₽ всего
- Длительность: 5 дней
- Метрика успеха: CTR(B) > CTR(A) * 1.5

**Результат после теста:** (заполняется после)
**Куда перенесли:** (working_combos.md / failed_combos.md)
```

## Накопленные интуитивные гипотезы (для проверки в будущих циклах)

Это **не подтверждённые** утверждения, а скорее «здравый смысл» от
Бобы и Vizit'а. Помечаем как «интуиция, проверить в реальном тесте».

### Интуиция Бобы (из его персоны и общего опыта правосл. ниш):

- Креатив с конкретным праздником (Радоница, Великий пост) работает лучше
  чем общий призыв «помолитесь о близких» в одинаковых условиях
- Образ свечи в полумраке цепляет сильнее чем икона на белом фоне
- Текст «Помяните рабов Божиих» работает в православной среде, но
  холоден для широкой аудитории — нужен мягкий перевод
- Lookalike от существующих 62k подписчиков pomolimsy даст лучший CPL
  чем парсинг подписчиков других сообществ (плотность ЦА выше)

### Интуиция Vizit'а (как владельца сообщества):

- Большинство имён присылают женщины зрелого возраста (41-58)
- Пик активности — перед родительскими субботами и в Великий пост
- Те кто пишет имена раз — часто пишут снова через 1-2 месяца
  (повторные пожертвования)

**Все эти утверждения — гипотезы.** До реального теста с n≥100 кликов
не делаем на их основе серьёзных решений.


## H1: База 619k горячих православных через TargetHunter

**Дата создания:** 2026-05-16
**Автор:** Claude (после ночной работы с TargetHunter совместно с Vizit'ом)
**Статус:** **БАЗА СОЗДАНА, ждёт первого реального теста**

**Контекст создания базы:**

Наш собственный парсер (`/vk_audience` через VK API service token)
уперлся в VK flood control при попытке парсить 12 групп параллельно.
VK API заблокировал токен ошибкой 9 (Flood control). Pivot — стали
использовать TargetHunter (профессиональный инструмент маркетинга
VK с 2015 года, у него пул токенов и обход rate limit).

**Этапы сбора (TargetHunter, ночь 16.05.2026):**

1. Поиск сообществ по ключам: «православие, батюшка, монастырь, храм,
   икона, молитва, поминовение, помянуть, упокой, святой» — каждое
   слово с новой строки, минимум 5000 участников, без геофильтра.
   **Результат:** 1 437 групп.

2. Ручная фильтрация по названиям (Vizit, 10-15 минут) — убраны
   антицифровые конспирологи («Мы не цифра»), эзотерика-маскировки,
   радикалы, политические агрессивные. **Осталось:** 484 группы.

3. Парсинг подписчиков в TargetHunter:
   - Источник: 484 группы
   - Состоят в 3+ группах одновременно (горячее ядро)
   - Архивные подписчики включены
   - Результат: **860 947 ID**

4. Фильтрация (универсальный фильтр TargetHunter):
   - Минус-сообщество: pomolimsy (исключить наших 62k)
   - Активность: онлайн за последние 14 дней
   - Только живые пользователи (не banned/deleted)
   - С фотографией (фильтр от ботов)
   - География и пол НЕ применялись (VK Ads сам сужает в кампании
     через targetings + большинство гео не указано в профилях)
   - **Финальный результат: 619 146 чистых горячих ID**

5. Загрузка через `/upload_audience` команду в Telegram-бот →
   VK Ads ремаркетинг сегмент **ID 80507749**, название
   «TargetHunter 2026-05-16 (619k IDs)».

**Что это значит:**

- У нас есть **готовая база на 6-12 месяцев тестов и циклов**
- Это **активные** православные **не из pomolimsy** которые состоят
  в 3+ правосл. сообществ — самое горячее ядро
- Может использоваться как **ремаркетинг-сегмент** в любых будущих
  кампаниях. Можно сужать в VK Ads через targetings (возраст 41-58,
  женщины, гео) для конкретных тестов
- На этой базе можно строить **lookalike** в Phase 12+ когда дойдём

**Гипотеза для теста (smoke test):**

База качественная и при правильном креативе даст CPL ≤50₽ на подписчика
в pomolimsy. Конкретно — на тёплом нейтральном креативе про молитвенную
поддержку (без коммерции, без монастыря в этом тесте) ожидается:
- CTR ≥0.5% (минимальная норма)
- CPC ≤15₽
- CPL ≤50₽ (если 30% от кликнувших дойдут до подписки/имени)

**Как проверить:** smoke test 1500₽ × 3 дня = 500₽/день на этом сегменте
с минусом pomolimsy в исключениях кампании. Один креатив, один сегмент,
без A/B (проверяем работоспособность цепочки, не оптимизируем).

**Куда перенести после теста:** working_combos.md (если CPL ≤50₽) или
failed_combos.md (если выше 100₽).

## H2: VK service token не подходит для массового парсинга

**Дата создания:** 2026-05-16
**Автор:** Claude (после flood control инцидента)
**Статус:** **ПОДТВЕРЖДЕНО** опытом

**Гипотеза:** Service token VK Ads для нашего приложения имеет жёсткие
лимиты на `groups.getMembers`. При попытке парсить 12 групп с
пагинацией (тысячи запросов за минуту) VK блокирует токен ошибкой 9
(Flood control). Блокировка временная (15-60 минут).

**Подтверждено наблюдением:** 16.05.2026 ~22:52 запуск /vk_audience full
дал ошибку, `/vk_parse pravoslavnie_hristiane 100` выдал ошибку 9.
`/vk_check` (другой endpoint groups.getById) продолжал работать —
лимит конкретно на `groups.getMembers`, не на токен целиком.

**Вывод:** Для массового парсинга подписчиков **использовать
TargetHunter**, не наш собственный парсер. Наш парсер остаётся для
ad-hoc проверок одной группы (типа /vk_parse) — там нагрузка маленькая,
flood control не срабатывает.

**Технический долг:** добавить в наш парсер rate limiting + retry
с экспоненциальным backoff на случай если будем парсить через свой
токен в будущем. Не приоритет — пока TargetHunter решает проблему.

**Куда перенести:** этот пункт остаётся в hypotheses как
архитектурное решение и lesson learned.
