# VK Реклама — карта функционала и roadmap бота

Документ-обзор всех возможностей нового кабинета **VK Ads (ads.vk.com)**: что
платформа умеет, что бот уже автоматизирует, что приоритетно добавить дальше.
Используется как навигатор при планировании Phase 4+.

Источники: документация VK Ads (`ads.vk.com/doc/api`), статьи по запуску
рекламы 2024-2026, личный опыт пользователя через прошлогодние n8n-интеграции.

---

## 1. Цели рекламных кампаний (objective)

VK Ads поддерживает **9 целей**. Каждая определяет объект продвижения и
оптимизацию.

| Objective | Что продвигаем | Бот использует? |
|---|---|---|
| `socialengagement` | Сообщества VK/OK (подписки, вступления) | ✅ Да — текущий default |
| `traffic` / `site_traffic` | Внешний сайт/лендинг | ❌ Можно добавить |
| `mobile_app` | Установки/события мобильного приложения | ❌ — |
| `mobile_app_install` | Установки приложения | ❌ — |
| `lead_form` | Лид-форма внутри VK (без сайта) | ❌ Перспективно |
| `vk_mini_app` | VK Mini Apps | ❌ — |
| `catalog_product` / `dynamic_remarketing` | Товарный фид (e-commerce) | ❌ — |
| `music_listens` | Прослушивания музыки | ❌ — |
| `video_views` | Просмотры видео | ❌ — |

**Что важно для бота:** мы заточены под `socialengagement` (подписки в
сообщество). Если потребуется промо сайтов/лендингов — добавим `traffic`
с другим CTA и URL вместо community ID.

## 2. Таргетинги (targeting) — что доступно

### 2.1 География

- **Регионы**: список ID (`regions: [188]` = Россия)
- **Города**: точечный выбор из справочника
- **Геоточка на карте**: круг радиусом N км вокруг адреса/координат
- **Исключения**: указать регионы/города, которые НЕ показывать

**Бот сейчас:** только Россия (regions=[188]). Можно расширить до выбора
конкретных городов через подпись пользователя или env var.

### 2.2 Демография

- **Пол**: `["male"]`, `["female"]`, `["male", "female"]`
- **Возраст**: `age_list` — массив конкретных лет (например, `[41, 42]`)
- **Семейное положение**: одинокие / в отношениях / женат-замужем

**Бот сейчас:** делает A/B сплит по возрасту (5 окон по 2 года), оба пола.
Можно добавить дополнительный сплит по полу — будет 10 групп вместо 5.

### 2.3 Интересы и поведение

- **Категории интересов**: ~100 рубрик из справочника VK (авто, спорт, еда, и т.д.)
- **Несколько интересов = расширение** аудитории (логика OR), не сужение
- **Чтобы сузить — нужны исключения**

**Бот сейчас:** интересы не использует. **Высокий приоритет на Phase 4** —
по теме рекламы Claude может подобрать релевантные категории интересов.

### 2.4 Ключевые фразы (контекстный таргетинг)

- Фразы которые пользователь искал или видел в карточках товаров
- Период поиска: 3-5 дней (горячий) или больше (тёплый)
- Минус-слова для исключения мусора
- **Между интересами и фразами — оператор И** (сужение)

**Бот сейчас:** не использует. **Phase 5 опция** — Claude может из темы
вытащить ключевые фразы (например, «молитвы за здравие» → ["молитвы",
"храм рядом", "записка о здравии"]).

### 2.5 Сообщества (community targeting)

- Показ подписчикам конкретных VK-сообществ
- Можно указать N сообществ списком
- **Похожая аудитория на сообщества** — VK сам подбирает

**Бот сейчас:** не использует. Очень полезно для нишевой православной
темы — таргет на подписчиков других монастырей/духовных каналов.

### 2.6 Устройства

- Тип устройства: десктоп / мобайл / планшет
- ОС: iOS / Android / Windows / macOS
- Версия ОС
- Производитель устройства (для мобайла)
- Язык интерфейса

**Бот сейчас:** не использует. Низкий приоритет.

### 2.7 Аудитории / Audiences (раздел «Аудитории»)

Это самое мощное:

#### A) **Списки контактов из CRM**
- Загрузка CSV/TXT с email/phone
- Минимум ~2000 контактов для запуска
- Файл до 128 МБ

#### B) **Похожие аудитории (Lookalike)**
- На основе пикселя, CRM-списка или существующей аудитории
- VK сам ищет похожих пользователей

#### C) **Аудитории из пикселя**
- Посетители сайта (все или с конкретным событием)
- Например: «не купил, но смотрел корзину»
- События кастомные через JS-конструктор

#### D) **Перенос из старого кабинета VK / myTarget**
- Кнопка «Перенести аудитории» — копирует списки ≥2000 пользователей

#### E) **Контекстные аудитории**
- На основе ключевых фраз, которые пользователь искал

**Бот сейчас:** не использует ни одну. **Это весь Phase 5.** API endpoints:
- `GET /remarketing/segments.json` — список аудиторий
- `POST /remarketing/segments.json` — создать
- `GET /remarketing/pixels.json` — пиксели

## 3. Форматы рекламы (creative formats)

| Формат | Использование | Бот делает? |
|---|---|---|
| **Универсальное объявление** | Главный формат, адаптируется под все площадки | ✅ Это и есть наш текущий формат |
| **Карусель** (несколько карточек) | Несколько товаров/преимуществ, листать | ❌ Можно добавить |
| **Видеореклама** | Ролик до 30 сек | ❌ Phase 6+ |
| **Коллаж** (несколько картинок одной композицией) | Только в старом кабинете | ❌ Не доступен в новом |
| **Товарный каталог (динамический ремаркетинг)** | Авто-генерация из фида товаров | ❌ E-commerce фича |
| **Лид-форма** (форма прямо в объявлении) | Без сайта, заявка внутри VK | ❌ Phase 6 |

**Бот сейчас:** делает универсальное объявление с одной картинкой.

### Размеры картинок (требования)

Для полноценного universal-объявления VK хочет **3 размера**:
- `image_256x256` — иконка
- `image_600x600` — квадрат для лент
- `image_1080x607` — горизонтальный для full-screen форматов (16:9 ish)

**Бот сейчас:** грузит только один размер (как `image_600x600`). Phase 4 —
добавить авто-ресайз через Pillow → грузить все 3 размера → лучше
адаптируется под площадки.

## 4. Стратегии ставок (autobidding_mode)

| Стратегия | Логика |
|---|---|
| `min_price` (минимальная цена) | Оптимизация под минимальную цену показа/клика |
| `max_price` (предельная цена) | Не выше указанной цены за результат |
| `max_goals` (максимум целей) | Максимум конверсий в рамках бюджета |
| Manual (ручная ставка) | Указать `max_price` точно |

**Бот сейчас:** использует `max_goals` (по умолчанию). Хорошо для большинства
случаев. Phase 4 — Claude может подсказать когда переключиться на `min_price`
для дешёвого охвата.

---

## 5. Площадки размещения (placements)

В новом кабинете можно **управлять каждой площадкой отдельно**:

- VKontakte (лента, истории, клипы, музыка, видео)
- Одноклассники (лента, мессенджер)
- Mail.ru (главная, почта)
- Партнёрская сеть (внешние сайты)

**Бот сейчас:** оставляет дефолтные настройки (все площадки). Это норма
для теста — потом можно отключить дорогие/неэффективные.

## 6. Пиксель и трекинг конверсий

- **Установка пикселя**: через раздел «Сайты» → «Добавить пиксель»
- **JS-код** на сайт
- **Стандартные события**: страница, корзина, покупка, регистрация
- **Кастомные события**: визуальный конструктор без программиста
- **Цели кампании**: переходы / заявки / покупки — для оптимизации

**Бот сейчас:** не работает с пикселями. Не нужно для нашего use case
(подписки в сообщество). Релевантно если пользователь начнёт продвигать сайты.

## 7. Каталог сообществ (для targeting + ad_object)

- В кабинете есть раздел «Сообщества» → можно привязать VK-сообщества
- Привязанные используются как:
  - `ad_object` — куда вести (что продвигаем)
  - Targeting — показ подписчикам этого сообщества
  - Targeting — похожая аудитория на подписчиков

**Бот сейчас:** использует `community_url_id` из env var. Можно усилить —
давать пользователю выбор из списка сообществ через `/communities` команду.

## 8. Бюджеты и расписание

- **Дневной бюджет**: `budget_limit_day` (рубли, целое число)
- **Общий бюджет**: `budget_limit` (за всё время кампании)
- **Дата старта/конца**: `date_start`, `date_end` (YYYY-MM-DD)
- **Расписание показов**: время дня, дни недели (dayparting)
- **Минимальная сумма пополнения**: уточняется

**Бот сейчас:** дневной бюджет настраивается, длительность 7 дней по
умолчанию. Phase 4 — добавить dayparting (показывать только в активные
часы целевой аудитории).

## 9. Статистика и аналитика

### Endpoints API

- `GET /statistics/ad_plans/day.json` — по кампаниям, по дням
- `GET /statistics/ad_groups/day.json` — по группам, по дням
- `GET /statistics/banners/day.json` — по баннерам
- Параметры: `date_from`, `date_to`, `id` (через запятую), `metrics`

### Доступные метрики (`metrics=all`)

```
total.base.shows         — показы
total.base.clicks        — клики
total.base.spent         — потрачено (₽)
total.base.cpm           — стоимость 1000 показов
total.base.cpc           — стоимость клика
total.base.cpa           — стоимость целевого действия
total.base.ctr           — кликабельность (%)
total.base.goals         — достижение целей
total.uniques.total      — уникальные пользователи
total.uniques.frequency  — частота показов на пользователя
total.uniques.increment  — прирост уникальных
total.romi.romi          — ROMI (если настроена ценность конверсии)
```

**Бот сейчас:** методы для чтения этих метрик есть (`get_campaign_stats`,
`get_ad_groups_stats`), но **не вызываются** — scheduler заглушка. Phase 4 —
подключить scheduler к реальным данным + утренние отчёты с инсайтами от Claude.

### Срезы статистики

- По дням / неделям / месяцам
- По полу (`gender_age` метрики)
- По возрасту
- По устройствам
- По регионам/городам
- По времени дня (dayparting analysis)

## 10. Иерархия объектов — как всё связано

```
АККАУНТ (cabinet)
└── Кампании (Ad Plans) — objective + budget + dates
    └── Группы объявлений (Ad Groups) — targetings + бюджет на группу
        └── Объявления (Banners) — креатив (текст + картинка/видео)
```

**Бот сейчас:** создаёт всё одной POST-операцией на `/ad_plans.json` с
вложенными группами и баннерами. Можно делать частично:
- POST `/ad_plans.json` — кампания
- POST `/ad_groups.json` (со ссылкой на ad_plan_id) — группы
- POST `/banners.json` — баннеры
- Это даёт гибкость добавлять группы в существующую кампанию

## 11. Ограничения и нюансы

- **Минимум для аудитории**: ~2000 пользователей
- **Лимит токенов API**: ~5 активных одновременно (бот теперь кэширует через БД, не упрёмся)
- **Модерация**: ручная, 1-24 часа
- **Без картинки баннер не создать** — VK Ads support подтвердили
- **ЕРИР/ОРД**: автоматическая маркировка для всех кампаний (новые нормы РФ)
- **Permanent токены**: тоже считаются в лимите 5

## 12. Roadmap бота — приоритеты по этапам

### ✅ Phase 1-3.5 (готово)
- OAuth, persistent caching, permanent token
- Чтение кабинета (campaigns, balance attempt)
- Создание кампании с возрастным A/B сплитом (5 групп × 2 года)
- Photo handler с генерацией 4 вариантов текста через Claude
- Inline-выбор варианта + создание

### Phase 4 — Анализ и оптимизация (когда появятся данные)
**Высокий приоритет:**
- [ ] `/analyze` — агрегированная аналитика кабинета через Claude
- [ ] Подключить scheduler к реальным метрикам (каждые 15 мин)
- [ ] Утренние отчёты с инсайтами (что вырвалось вперёд, что стоит отключать)
- [ ] Auto-pause слабых групп (CTR ниже порога, или CPA выше лимита)
- [ ] Auto-scale удачных (увеличить бюджет в 1.5× для лидеров)

**Средний приоритет:**
- [ ] Multi-size картинки (256/600/1080) через Pillow
- [ ] `/winners` и `/losers` команды

### Phase 5 — Аудитории и ремаркетинг
**Высокий:**
- [ ] `/audiences` — список существующих сегментов
- [ ] Авто-создание сегмента «кликнувшие за 30 дней» из кампании
- [ ] Lookalike из конвертеров для новых A/B тестов
- [ ] CRM-загрузка через бот (CSV из Telegram → API)

**Средний:**
- [ ] Targeting по сообществам (показ подписчикам других монастырей)
- [ ] Контекстные ключевые фразы (Claude генерит из темы)

### Phase 6 — Расширение форматов
- [ ] Карусели (несколько товаров/преимуществ)
- [ ] Лид-формы (без сайта)
- [ ] Видеореклама (если будет генерация видео)
- [ ] Targeting по интересам (Claude подбирает категории из темы)

### Phase 7 — Production-ready
- [ ] Postgres вместо SQLite (надёжное хранение токенов и данных)
- [ ] Multi-cabinet support (если несколько кабинетов)
- [ ] Multi-project routing (Зеленецкий vs другие проекты)
- [ ] Inline keyboard для всех действий (вместо текстовых команд)
- [ ] Уведомления о модерации (вебхук от VK)

## 13. Что бот **не будет** делать (out of scope)

- Создание сайтов/лендингов (для objective=traffic пользователь готовит сам)
- Работа с пикселями (объект для отдельного веб-разработчика)
- Дизайн креативов (картинки даёт пользователь, AI image gen вне scope MVP)
- Бухгалтерия/закрывающие документы
- Парсинг сторонних сообществ (нарушает ToS VK)
