## Большая идея (от Vizit'а)

Каждый агент команды (Боба, Кирилл, Тимур, Рита, Алина, Артём, Биба) получает **свой Telegram-бот** через `@BotFather`. Все они живут в **одной групповой беседе** Telegram вместе с Vizit'ом. Агенты **общаются между собой простым языком** когда есть триггеры (модерация прошла, Сторож алёртит, утреннее планирование).

Vizit может в любой момент зайти в чат и:
- Видеть как агенты обсуждают текущие задачи
- Подкидывать им свои идеи
- Получать ответы от того агента кому это адресовано

**Вечернее совещание** — каждый вечер автоматически по cron агенты собираются и обсуждают итоги дня. Утром Vizit читает резюме.

## Что уже сделано (Phase 5.15) — `bb6056c`

### Архитектура multi-bot в одном процессе

`src/main.py` теперь запускает **два Application параллельно**:
- Главный бот (Claude — диспетчер команд /launch_batch, /watchdog, /pause, etc.)
- Боба-бот (если задан `TG_BOT_BOBA_TOKEN`)

Оба работают через неблокирующий `application.start()` + `updater.start_polling()`. Корректное завершение через `application.stop()` + `application.shutdown()` в finally блоке.

### Боба как отдельный бот

`src/telegram_bots/boba_bot.py`:

- **`BOBA_GREETING`** — стартовое сообщение Бобы (стиль: серьёзный, без воды, как CMO с 13-летним стажем)
- **`boba_start(/start)`** — приветствие + сброс истории
- **`boba_handle_message`** — текстовое сообщение → ответ через `DialogAgent(BOBA_PERSONA).chat()`. История хранится в `context.user_data['boba_history']`, обрезается до 20 сообщений (10 пар).
- **`boba_reset(/reset)`** — очистить историю
- **`_build_project_context()`** — динамический контекст текущего проекта. Добавляется к каждому запросу пользователя:
  - Количество активных кампаний в VK Ads
  - Имена последних 5 кампаний
  - Кампании которые Сторож пометил как проблемные (из `bad_campaigns_state`)
  - Время последнего запуска Сторожа
- **`build_boba_application()`** — конструктор Application. Возвращает None если токен не задан. Фильтр owner — отвечает только Vizit'у.

### Phase 5.17 — Межагентные диалоги

**Самая сложная часть.** Сейчас каждый агент отвечает только Vizit'у в личке. Нужно сделать так чтобы:

1. **Vizit создаёт групповую беседу** в Telegram и добавляет туда всех ботов + себя
2. **Агенты могут писать в группу** не только в ответ на сообщение, но и **по триггерам**:
   - Сторож нашёл проблемные кампании → Алина пишет в группу краткий отчёт → Боба отвечает «Кирилл, нужны новые тексты на 47-52»
   - Модерация прошла → Тимур пишет «12 кампаний активны, бюджет пошёл»
   - Vizit пишет «А что если попробовать [...]?» → Claude-диспетчер определяет кому это адресовано → нужный агент отвечает

**Технически:**
- В коде — `src/telegram_bots/conversations/dispatch.py`. Логика «кто отвечает» через системный промпт Claude-диспетчера: «прочитай сообщение, реши кому из {Боба, Кирилл, Тимур, Рита, Алина} это лучше передать»
- Триггеры через event bus (apscheduler + наши собственные события)
- Каждый бот шлёт сообщения в **общий chat_id группы** через `application.bot.send_message(chat_id=GROUP_CHAT_ID, ...)`

### Phase 5.18 — Вечернее совещание

`apscheduler` запускает скрипт в 21:00 каждый день:

```
[21:00] @Boba: Итоги дня. Алина, что у нас?
[21:01] @Alina: ... отчёт ...
[21:03] @Boba: Кирилл, нужны идеи на завтра. Что предлагаешь?
[21:04] @Kirill: ... 3 варианта ...
[21:06] @Boba: Тимур, бюджет позволяет?
[21:07] @Timur: ... технические детали ...
[21:09] @Boba: ОК, на утро план готов. Vizit прочитает.
```

Каждая реплика — отдельный Anthropic API вызов с персоной агента. Контекст разговора передаётся в каждый следующий запрос. Общая стоимость одного совещания: ~30k токенов = ~$0.5.

## Открытые архитектурные вопросы для нового чата

1. **Кто инициирует межагентные диалоги?** Сторож шлёт алерт прямо в группу → Алина видит и комментирует → Боба видит и зовёт Кирилла. Или централизованный диспетчер?

2. **Контекст разговора** — каждый агент держит свою историю в `user_data`, или общая история на всю группу?

3. **Стоимость API** — Sonnet 4 модель, ~$3-5/мес на дневные совещания. Если использовать Haiku 4.5 — в 3-5 раз дешевле, но менее качественные ответы. Какой trade-off?

4. **Конфликты между агентами** — что если Кирилл и Тимур не согласны? Боба должен принять решение. Кодить логику разрешения конфликтов?

5. **Память между днями** — агенты должны помнить вчерашние результаты. Простой PostgreSQL в `src/db/` или JSON-файл `agent_memory.json`?
