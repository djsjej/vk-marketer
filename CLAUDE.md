# VK AI-маркетолог — инструкции для Claude Code

## Что это за проект

Telegram-бот, который автоматически управляет рекламой VK для православного контента (Зеленецкий монастырь, Святой Спиридон). Работает 24/7 на Railway.

**Что делает бот (MVP, версия 1):**
1. Принимает от пользователя картинки и темы через Telegram
2. Создаёт A/B тесты в VK Рекламе (несколько вариантов текста на одну картинку)
3. Мониторит метрики (CTR, CPM, CPL)
4. Автоматически отключает плохие, масштабирует хорошие
5. Контролирует бюджет через жёсткие правила
6. Отчитывается утром в Telegram

**Что НЕ делает (явно вне scope в MVP):**
- Не генерирует картинки автоматически — пользователь сам присылает
- Не пишет посты в группе монастыря — только рекламу
- Не выходит за рамки заложенных правил без подтверждения

## Технологический стек

- **Python 3.11+**
- **python-telegram-bot** — Telegram бот
- **httpx** — HTTP клиент для VK Ads API
- **APScheduler** — планировщик задач
- **SQLAlchemy + SQLite** — БД (на Railway апгрейдим до Postgres при необходимости)
- **anthropic** — Claude SDK для анализа и генерации текстов
- **Railway** — хостинг

## Принципы работы

**1. Безопасность бюджета — приоритет №1.**
Всё, что касается денег, должно проходить через `scheduler/safety.py`. Жёсткие правила в коде, не делегируем Claude.

Примеры правил:
- Если расход за день превысил `MAX_DAILY_SPEND` — стоп всё
- Если расход за час > `HOURLY_THRESHOLD` без кликов — пауза кампании
- Никогда не запускать кампанию без подтверждения в Telegram, если бюджет > `AUTO_LAUNCH_LIMIT`

**2. Human gate для нетривиальных решений.**
Бот предлагает действия, человек подтверждает в Telegram inline-кнопкой. Без подтверждения — только дешёвые/обратимые действия (старт теста на 200₽, остановка кампании).

**3. Логирование всего.**
Каждое действие бота логируется в БД и в Telegram (с разной детализацией). При отладке смотрим логи.

**4. Тон под православную аудиторию.**
Тексты объявлений должны быть в православной стилистике, без мирских клише. См. `claude_brain/copywriter.py` — там промпт-шаблоны.

## Переменные окружения

Все ключи в `.env` (локально) или Railway env vars (продакшен). Никогда не коммитим.

Список см. в `.env.example`.

## Как развёртывать

Railway автоматически подхватывает push в `main`, билдит по `Procfile`, запускает.

Локальный запуск для разработки:
```bash
pip install -r requirements.txt
cp .env.example .env  # заполнить ключами
python -m src.main
```

## Известные эндпоинты VK Ads API

- **OAuth:** `POST https://target.my.com/api/v2/oauth2/token.json` (grant_type=client_credentials)
- **API base:** `https://target.my.com/api/v2/`
- **Account:** `GET /users/current.json`
- **Кампании:** `GET /campaigns.json` (поля: id, name, status, budget_limit_day)
- **Стата:** `GET /statistics/campaigns/{ids}/day.json` (date_from, date_to)

⚠️ Бюджеты VK хранит в **копейках** — конверсия rub*100 при записи, /100 при чтении.

## Coding conventions

- Python 3.11+, async/await везде где возможно
- Type hints обязательны на публичных функциях
- Pydantic для всех внешних данных (VK API responses, Telegram payloads)
- Логирование через `logging`, форматтер JSON для Railway
- Тесты в `tests/`, pytest, моки для внешних API
